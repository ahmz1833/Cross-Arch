# مستندات معماری s390x (IBM z/Architecture)

این سند شامل توضیحات تکمیلی در مورد معماری s390x، ساختار دستورات، رجیسترها و قراردادهای فراخوانی توابع است.

## ۱. ساختار و نام‌گذاری دستورات (Mnemonics)

در معماری s390x، نام دستورات (Mnemonics) دارای ساختار مشخصی است که به فهم عملکرد آن‌ها کمک می‌کند.

### پسوندها و پیشوندها

*   **`G` (Great / 64-bit):** اگر در نام دستور حرف `g` وجود داشته باشد، به این معنی است که عملیات روی داده‌های ۶۴ بیتی انجام می‌شود.
    *   مثال: `lgr` (Load 64-bit Register)
*   **`F` (Full word / 32-bit):** اگر حرف `f` بعد از `g` بیاید، به معنی این است که ورودی ۳۲ بیتی است اما به ۶۴ بیت Sign-Extend می‌شود.
    *   مثال: `lgfr` (Load Great Full Register) - ۳۲ بیت پایین رجیستر مبدا را می‌خواند، علامت را گسترش می‌دهد و در رجیستر ۶۴ بیتی مقصد می‌ریزد.
*   **`H` (Half word / 16-bit):** عملیات روی داده‌های ۱۶ بیتی.
*   **`RL` (Relative with Label):** دستوراتی که با `rl` ختم می‌شوند، از آدرس‌دهی نسبی (Relative Addressing) استفاده می‌کنند و می‌توانند مستقیماً با Labelها کار کنند.
    *   مثال: `larl` (Load Address Relative Long), `lgrl`, `stgrl`.
    *   *نکته:* دستورات معمولی (بدون `rl`) معمولاً نیاز به Base Register دارند و نمی‌توانند مستقیماً با Labelهای دور کار کنند.
*   **`Y` (20-bit Displacement):** دستوراتی که به `y` ختم می‌شوند، دارای Displacement بیست بیتی هستند (در مقابل ۱۲ بیت استاندارد). این اجازه می‌دهد به آفست‌های بزرگتری دسترسی داشته باشید.
    *   مثال: `lay`, `sty`, `lgfi`.
*   **`I` (Immediate):** دستور با یک مقدار ثابت (Immediate) کار می‌کند.
    *   مثال: `lghi` (Load Great Halfword Immediate).
*   **`K` (3-Operand):** دستوراتی که سه عملوند می‌گیرند (مقصد و دو مبدا جداگانه).
    *   مثال: `ark` (Add Register 3-operand) -> `R1 = R2 + R3`.
*   **`L` (Logical):** عملیات بدون در نظر گرفتن علامت (Unsigned).
    *   مثال: `algr` (Add Logical Great Register).

### دسته‌بندی عملیات

حرف اول (یا دو حرف اول) معمولاً نوع عملیات را مشخص می‌کند:

*   **A**: Add (جمع)
*   **S**: Subtract (تفاضل)
*   **M**: Multiply (ضرب)
*   **D**: Divide (تقسیم)
*   **L**: Load (بارگذاری)
*   **ST**: Store (ذخیره)
*   **C**: Compare (مقایسه)
*   **B**: Branch (پرش)
*   **N**: AND
*   **O**: OR
*   **X**: XOR
*   **LA**: Load Address

### ساختار کلی دستور

بسیاری از دستورات از الگوی زیر پیروی می‌کنند:
`[Operation][Type/Size][SourceType]`

مثال: `LGHI`
*   **L**: Load
*   **G**: Great (64-bit destination)
*   **H**: Halfword (16-bit immediate source)
*   **I**: Immediate

## ۲. رجیسترها (Registers)

معماری z/Architecture دارای ۱۶ رجیستر عمومی ۶۴ بیتی است.

| نام | شماره | نقش (در قرارداد استاندارد لینوکس) |
| :--- | :--- | :--- |
| **R0** | 0 | استفاده‌های خاص سیستمی / گاهی به عنوان Scratch |
| **R1** | 1 | Scratch / گاهی برای هوک‌های سیستمی |
| **R2** | 2 | **آرگومان اول** / **مقدار بازگشتی** |
| **R3** | 3 | **آرگومان دوم** |
| **R4** | 4 | **آرگومان سوم** |
| **R5** | 5 | **آرگومان چهارم** |
| **R6** | 6 | **آرگومان پنجم** (ذخیره شونده توسط فراخوانده - Callee Saved در برخی مدل‌ها، اما در لینوکس معمولاً آرگومان است) |
| **R7 - R11** | 7-11 | متغیرهای محلی (Callee Saved) - باید مقدارشان حفظ شود. |
| **R12** | 12 | معمولاً به عنوان GOT Pointer (در کدهای PIC) یا Base Register استفاده می‌شود. |
| **R13** | 13 | اشاره‌گر به ناحیه داده‌های محلی (Literal Pool Pointer) یا ذخیره شده. |
| **R14** | 14 | **آدرس بازگشت** (Return Address). |
| **R15** | 15 | **اشاره‌گر پشته** (Stack Pointer). |

## ۳. کلمه وضعیت برنامه (PSW - Program Status Word)

در s390x، به جای یک رجیستر FLAGS ساده (مثل x86)، یک ساختار ۱۲۸ بیتی به نام PSW وجود دارد که وضعیت پردازنده را نگه می‌دارد.
*   **Instruction Address**: آدرس دستور بعدی (معادل RIP/PC).
*   **Condition Code (CC)**: دو بیت که وضعیت نتیجه عملیات قبلی را نشان می‌دهد (0, 1, 2, 3).
    *   بسیاری از دستورات پرش (Branch) بر اساس این CC عمل می‌کنند.
    *   مثال: `je` (پرش اگر CC=0)، `jl` (پرش اگر CC=1)، `jh` (پرش اگر CC=2).

## ۴. قرارداد فراخوانی توابع (Calling Convention)

در لینوکس روی s390x (استاندارد ELF ABI):

1.  **آرگومان‌ها:** ۵ آرگومان اول در `R2` تا `R6` قرار می‌گیرند. بقیه در پشته (Stack) و در ناحیه آرگومان‌ها (Argument Area) ذخیره می‌شوند.
2.  **بازگشت:** مقدار بازگشتی تابع در `R2` قرار می‌گیرد.
3.  **پشته (Stack):**
    *   پشته به سمت پایین رشد می‌کند.
    *   `R15` همیشه به بالای پشته اشاره می‌کند.
    *   هر تابع باید یک **Stack Frame** به اندازه حداقل ۱۶۰ بایت (در ۶۴ بیت) رزرو کند.
    *   این ۱۶۰ بایت شامل فضای ذخیره‌سازی رجیسترها (Register Save Area) برای تابع *فراخوانی‌کننده* است.

### ساختار Stack Frame (حداقل ۱۶۰ بایت)

```text
High Address
+-----------------------------+
| Back Chain (اشاره‌گر به فریم قبلی) |  <- R15 + 0
+-----------------------------+
| Reserved / EOS              |
+-----------------------------+
| R14 (Return Address)        |  <- R15 + 112 (توسط تابع Callee اینجا ذخیره می‌شود)
+-----------------------------+
| R15 (Previous SP)           |
+-----------------------------+
| ... (سایر رجیسترها)           |
+-----------------------------+
| Argument Area (برای توابع بعدی)|  <- R15 + 160
+-----------------------------+
Low Address (R15)
```

**نکته مهم:** وقتی تابعی را صدا می‌زنید (`brasl` یا `basr`)، آدرس بازگشت در `R14` ذخیره می‌شود. اگر تابع شما خودش تابع دیگری را صدا می‌زند، باید حتماً `R14` را در پشته ذخیره کند (معمولاً در آفست ۱۱۲ از R15) و قبل از بازگشت آن را بازیابی کند.
## ۵. حالت‌های آدرس‌دهی (Addressing Modes)

### ۵.۱. آدرس‌دهی D(X, B) - Base-Displacement

اکثر دستورات حافظه از فرمت `D(X, B)` استفاده می‌کنند:
*   **D**: Displacement (جابجایی) - عدد ثابت ۱۲ یا ۲۰ بیتی
*   **X**: Index Register (اختیاری)
*   **B**: Base Register (اختیاری)

آدرس نهایی = `D + Reg[X] + Reg[B]`

**نکته مهم:** در این حالت **نمی‌توان** مستقیماً از Label استفاده کرد! چون آدرس Label معمولاً بزرگتر از ۲۰ بیت است.

```asm
lg   %r2, 0(%r3)        /* Load از آدرس موجود در R3 */
lg   %r2, 8(%r3)        /* Load از آدرس R3 + 8 */
lg   %r2, 0(%r4, %r3)   /* Load از آدرس R3 + R4 */
```

### ۵.۲. آدرس‌دهی Relative (RL)

دستوراتی که به `RL` ختم می‌شوند از آدرس‌دهی نسبی به PC استفاده می‌کنند و **می‌توانند** مستقیماً با Label کار کنند:

```asm
larl %r2, my_label      /* آدرس my_label را در R2 بگذار */
lgrl %r2, my_data       /* مقدار موجود در my_data را Load کن */
stgrl %r2, my_data      /* مقدار R2 را در my_data ذخیره کن */
```

### ۵.۳. دستورات Y-دار (20-bit Displacement)

برخی دستورات قدیمی فقط ۱۲ بیت Displacement دارند. نسخه‌های `Y`-دار آن‌ها ۲۰ بیت دارند:

| دستور اصلی | نسخه Y-دار | توضیح |
| :--- | :--- | :--- |
| `L` | `LY` | Load (32-bit) |
| `ST` | `STY` | Store (32-bit) |
| `LH` | `LHY` | Load Halfword |
| `STH` | `STHY` | Store Halfword |
| `N` | `NY` | AND |
| `O` | `OY` | OR |
| `X` | `XY` | XOR |
| `S` | `SY` | Subtract |
| `STM` | `STMY` | Store Multiple |

> **نکته:** دستورات ۶۴ بیتی (با پسوند `G`) معمولاً به‌طور پیش‌فرض ۲۰ بیتی هستند و نیازی به نسخه Y ندارند.

## ۶. Extended Mnemonics (شبه‌دستورات)

دستوراتی مثل `je`, `jne`, `jl`, `jh`, `jle`, `jhe` در مستندات اصلی IBM نیستند! این‌ها **Extended Mnemonics** هستند که اسمبلر GNU آن‌ها را به دستورات واقعی ترجمه می‌کند.

| Extended | دستور واقعی | معنی |
| :--- | :--- | :--- |
| `je label` | `brc 8, label` | Jump if Equal (CC=0) |
| `jne label` | `brc 7, label` | Jump if Not Equal |
| `jl label` | `brc 4, label` | Jump if Low (CC=1) |
| `jh label` | `brc 2, label` | Jump if High (CC=2) |
| `jle label` | `brc 12, label` | Jump if Low or Equal |
| `jhe label` | `brc 10, label` | Jump if High or Equal |
| `jnz label` | `brc 7, label` | Jump if Not Zero |
| `jz label` | `brc 8, label` | Jump if Zero |

## ۷. دستورات شرطی (On Condition)

برخی دستورات نسخه شرطی دارند که با پسوند `C` یا `OC` مشخص می‌شوند و یک **Mask** می‌گیرند:

```asm
/* LOCGR: Load on Condition Great Register */
cgr   %r3, %r4           /* مقایسه R3 با R4 */
locgr %r2, %r5, 8        /* اگر Equal بود (CC=0, Mask=8)، R5 را در R2 بریز */

/* مقادیر Mask: */
/* 8 = Equal (CC=0) */
/* 4 = Low (CC=1) */
/* 2 = High (CC=2) */
/* 1 = Overflow (CC=3) */
```

## ۸. ضرب و تقسیم

### ضرب Single (نتیجه در یک رجیستر)

```asm
msgr %r2, %r3       /* R2 = R2 * R3 (64-bit × 64-bit → 64-bit) */
msr  %r2, %r3       /* R2 = R2 * R3 (32-bit × 32-bit → 32-bit) */
mghi %r2, 100       /* R2 = R2 * 100 (immediate) */
```

### ضرب Double (نتیجه ۱۲۸ بیتی در جفت رجیستر)

```asm
mgrk %r2, %r4, %r5  /* R2:R3 = R4 × R5 (64×64 → 128-bit) */
/* نتیجه: 64 بیت بالا در R2، 64 بیت پایین در R3 */
```

### تقسیم (نیاز به جفت رجیستر زوج-فرد)

تقسیم همیشه از یک **جفت رجیستر زوج-فرد** استفاده می‌کند (مثل R0:R1 یا R2:R3).

```asm
/* تقسیم 64 بیتی: */
lghi %r0, 0         /* بیت‌های بالای مقسوم را صفر کن */
lgr  %r1, %r6       /* مقسوم (dividend) در R1 */
lghi %r9, 10        /* مقسوم‌علیه (divisor) */
dsgr %r0, %r9       /* تقسیم R0:R1 بر R9 */
/* نتیجه: R0 = باقیمانده، R1 = خارج‌قسمت */
```

> **نکته:** در `dsgr`، رجیستر اول باید **زوج** باشد (R0, R2, R4, ...). خروجی در همان جفت ذخیره می‌شود: باقیمانده در زوج، خارج‌قسمت در فرد.

## ۹. نکته درباره Immediate

دستورات Immediate معمولاً با `FI` می‌آیند (مثل `LGFI`) چون:
*   فرمت دستورات s390x جایی برای immediate بزرگتر از ۳۲ بیت ندارد
*   `LGFI` یک immediate ۳۲ بیتی را Sign-Extend کرده و در رجیستر ۶۴ بیتی می‌ریزد

```asm
lgfi %r2, 0x12345678    /* R2 = 0x0000000012345678 */
lghi %r2, 100           /* فقط 16-bit immediate */
```
